Desktop app and CLI for gRPC, gRPC-Web, WebSocket and REST

gRPC requests you can commit.

Layang keeps requests, proto revisions, mocks and docs as YAML files in a workspace folder. The desktop app and the CLI open the same folder, so the request you debug at your desk is the one CI runs.

One window for the proto, the call and the stream.

Pick a method from the imported proto, edit the body against its message type, and read responses, metadata and each streamed message as it arrives.

From a .proto file to a check in CI.

Each step writes plain files into the workspace. Use the desktop app or the CLI for any of them; both read and write the same files.

  1. 1

    Import the proto

    Layang stores an immutable revision, so a request stays pinned to the schema it was written against.

    layang schema:import ./workspace --file samples/greeter.proto
  2. 2

    Send a request

    Unary or server-streaming, over native gRPC or gRPC-Web, with metadata, deadlines and assertions.

    layang run ./workspace --request "Say Hello"
  3. 3

    Mock the method

    Each scenario is its own YAML file. Start the mock server locally for the frontend team or for tests.

    layang mock:start ./workspace --protocol grpc
  4. 4

    Commit and check

    Review the diff like any other code. CI validates the workspace and runs the saved requests.

    layang validate ./workspace --json

A streaming mock is a file you can read.

This scenario answers WatchHello for Ayu with three messages, half a second apart, and plays the list twice. Edit it in the app or in your editor, then apply it to the running server.

input

Use this scenario only when the request matches: equals, contains, matches (regex), glob or headers.

intervalMs

Time between streamed messages. A single response can set its own delayMs.

maxLoops: 1

Restarts once after the first full pass, so the list plays twice. 0 keeps streaming until the client cancels.

Live Push

Keep the stream open and send the next saved response by hand while you watch the client.

    - data: { message: Bye, sequence: 3 }

What is in the folder.

Everything a teammate needs is tracked. Open tabs, window layout, absolute import paths and the last environment you used stay in .layang/, which the workspace .gitignore excludes, so opening a request never creates a diff.

layang.ymltrackedWorkspace name and file format versions.
collections/trackedOne YAML file per request, named by protocol: say-hello.grpc.yml, login.rest.yml, events.websocket.yml.
protos/trackedImmutable proto revisions with checksums. Changed sources become a new revision.
environments/trackedTargets and variables per environment.
mocks/trackedgRPC scenarios, one file each, plus REST and WebSocket mock configuration.
docs/trackedNotes you write and the static site layang docs:build generates. See an example.
.layang/ignoredMachine-local state that should not reach your teammates.

The same workspace runs in CI.

The standalone CLI bundles its own Node runtime. Unpack it on a runner, validate the workspace, start the mocks and fail the build when a saved request stops matching its assertions.

.github/workflows/api.yml
- name: Check API workspace
  run: |
    layang validate ./workspace --json
    layang mock:start ./workspace --protocol grpc --daemon
    layang run ./workspace --reporter junit --output api.xml
    layang mock:stop ./workspace
